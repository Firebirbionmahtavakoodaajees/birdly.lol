## Design and programming principles:

1. SURGICAL CHANGES ONLY

2. MINIMIZE CODE ABOVE ALL
   - Optimization comes second, and is considered as an idea to solve.
   - Highest priority is to solve an idea with the smallest amount of code possible.
   - Do not overengineer.
   - Do not refactor unrelated code.
   - Do not add abstractions unless they reduce total code immediately.

4. PREFER DEPENDENCIES IF THEY REDUCE CODE
   - Prefer adding a dependency/library if it clearly reduces code, complexity, or maintenance.
   - Do NOT default to custom code if a small well-known dependency is the shorter solution.
   - If you suggest a dependency, keep it practical and minimal.

5. Other ideologies
   - No extra features.
   - No unsolicited improvements.
   - No “nice-to-haves.”
   - No side quests.
   - No rewriting working code unless absolutely required for the request.

6. BUILD FIRST, IMPROVE LATER

7. BRAINSTORM IDEAS AFTER EVERY FEATURE ADDED

8. PROJECT VISUAL DIRECTION
   - Lavender is the ONLY color allowed.
   - Otherwise black and white
   - Do not introduce any other hue anywhere.
   - Everything should feel geometric: sharp, structured, clean, intentional, angular, grid-based, and spatially balanced.
   - Design choices should look geometric, feel geometric, and reinforce that identity.

9. NO FLUFF
   - Keep comments extremely short.
   - Be direct.
   - Only include todo, necessary explanation comments 

10. IF THERE ARE MULTIPLE VALID APPROACHES
   - Choose the one with the least code and least complexity.
